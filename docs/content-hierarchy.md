# 页面内容减法：让布局自己说话

2026-10-28 用户明确要求。适用于 UI、网页、表单及活动页面的新建、重构与验收。新规则覆盖旧规范中默认添加眉题、描述、能力标签的建议；用户明确指定必须保留的内容与实际业务约束优先。

## 默认原则

避免不必要的次要标签、说明文字、辅助文案、描述性文字和冗余微文案。用布局、视觉层级、间距、分组和清晰的主操作完成解释。默认不添加 slogan、纯装饰英文、教学段落或每个区块下的帮助说明；不是把这些文字缩小、淡化或藏到视觉之外。

按钮直接命名动作与对象，例如“选择品牌与款式”“开始 AI 鉴定”“保存收货信息”，不要再加“点击这里即可……”的说明。同一个事实在当前决策点表达一次；标题、卡片、标签和按钮不重复讲同一句话。精简文案不能增加新业务承诺或改变发券、计次、支付、有效期等规则。

非必需的细节优先收进有名称的 info 按钮与 tooltip / popover，或语义明确的折叠区。触屏可点击，键盘可聚焦、展开和关闭，关闭后焦点合理返回；不能只有 hover 或原生 title。不要为了删一句短文而制造一排问号图标。

## 必须保留的边界

- 表单保留可见 label 与程序关联；图标按钮保留可访问名称。placeholder 不代替 label，不能靠颜色或图形猜含义。
- 错误、成功、加载、禁用原因应在需要时出现，并供读屏软件感知。尚未选择品牌时，通过明确的选择控件和状态表达下一步，不添加重复教学段落。
- 删除、支付、永久提交或放弃限时权益等危险 / 不可逆操作，在决定发生前就近显示后果；金额、扣券数、失效时间等影响决定的条件不得藏进 tooltip。
- 必要隐私提示、模拟结果标记与能力边界保持真实可见，但同一事实不在每个区块重复铺开。报告结果处的关键限制不能只留在页面外的说明文件中。

## 重构与验收顺序

1. 标出每段文字的用途：任务信息、动作、状态、决策条件、可选细节或纯装饰。
2. 删除重复与纯装饰文案，同时清理空容器、无用样式和重复绑定；不能只用 CSS 隐藏。
3. 用分组、对齐、留白和明确按钮补足结构；按需收起可选细节。保留功能入口，不以精简为由删功能。
4. 检查首次使用：用户能否看懂下一步点哪里、点击会发生什么？若不清楚，先改布局、按钮或状态，再考虑必要的一句说明。
5. 检查 320 / 390 / 430 宽度、长文案、空状态、已选状态、键盘及触屏。确认 label、可访问名称、错误反馈、费用 / 扣券 / 放弃后果没有丢失。

## 代表性判断

| 场景 | 默认处理 | 保留的信息 |
| --- | --- | --- |
| 服务入口已有明确名称与主操作 | 删重复标题、泛化 slogan 和能力胶囊 | 用户必须知道的服务对象与限制 |
| 上传后需要选款式 | 用“选择品牌与款式”按钮和有 label 的字段 | 选中值、失败反馈、模拟标记 |
| 活动卡片 | 活动名、日期或状态、清晰入口即可 | 真正影响参与的有效期 / 条件 |
| 扣券或放弃领取 | 不用小字弱化重要条件 | 本次扣券数、关闭后的不可补领后果 |
| 演示工具与规则细节 | 收进“演示选项”或“规则” | 展开后的清晰操作及重置后果 |
